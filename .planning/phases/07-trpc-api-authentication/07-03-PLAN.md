```typescript
  referencePeriod: number; interestRate: number; inflationRate: number; treatedFloorArea: number;

  costItems: CostItemInput[]; serviceComponents: ServiceComponentInput[];
  buildingElementMaintenancePercent: number; wlcInput: WLCInputData;
  designCosts: DesignCostInput[]; incomeInput?: IncomeInputData;
}
export interface IncomeInputData { rents: { monthlyPerM2: number; area: number; taxes: number }[]; otherIncomes: { amount: number; taxes: number }[]; expectedPricePerM2?: number; }
export interface WLCInputData { landCost: number; enablingCosts: number; planningFees: number; userSupportPropMgmt: number; userSupportCharges: number; userSupportAdmin: number; financeCost: number; designCostsTotal: number; siteManagementCostsTotal: number; }
```

Prisma models used for variant sections:
- Geometry: variantId (unique), ~15 Decimal fields (grossFloorArea, netFloorArea, treatedFloorArea, etc.)
- BoundaryCondition: variantId (unique), referencePeriod (Int), interestRate (Decimal), inflationRate (Decimal), energyPrices (Json)
- EnergyInput: variantId + endUse (unique), energySourceIndex, specificConsumption, pvProductionKwh
- WLCInput: variantId (unique), ~12 Decimal fields
- DesignCost: variantId (not unique, multiple rows), lineNumber, description, 4 Decimal cost fields
- IncomeInput: variantId (unique), 15 flat Decimal fields for rent1/2/3 and otherIncome1/2/3
- MaintenanceConfig: variantId (unique), buildingElementMaintenancePercent (Decimal)
- ServiceComponent: variantId (not unique, multiple rows), name, constructionCost, en15459ComponentIndex
- CostItem: variantId + category, materialCostAgg, laborCostAgg, otherCostAgg, details[]

**src/server/trpc/routers/calculation.ts** - Engine integration:

Import `z` from `"zod"`, `createTRPCRouter`, `protectedProcedure` from `"../init"`, `TRPCError` from `"@trpc/server"`, `calculateLCC`, `DEFAULT_ENGINE_CONFIG` from `"@/engine"`, and engine types.

Helper `d(val: unknown): number` for Decimal-to-number conversion (same pattern as variant router).

Helper `buildVariantInput(variant: FullVariantWithRelations): VariantInput`:
- Takes the Prisma variant object with all eagerly-loaded relations
- Converts every Decimal field to plain number using `d()`
- Maps Prisma models to engine input interfaces:

  ```
  referencePeriod: variant.boundaryCondition.referencePeriod
  interestRate: d(variant.boundaryCondition.interestRate)
  inflationRate: d(variant.boundaryCondition.inflationRate)
  treatedFloorArea: d(variant.geometry?.treatedFloorArea)
  energyPrices: variant.boundaryCondition.energyPrices (JSON, already number[])
  energyInputs: variant.energyInputs.map(row => ({
    endUse: row.endUse,
    energySourceIndex: row.energySourceIndex,
    specificConsumption: d(row.specificConsumption),
    pvProductionKwh: row.endUse === "PV_PRODUCTION" ? d(row.pvProductionKwh) : undefined,
  }))
  costItems: aggregate from variant.costItems using resolveDetailCost for each detail (MAX(mat, unit*area) resolution per architecture decision)
  serviceComponents: variant.serviceComponents.map(sc => ({
    name: sc.name,
    constructionCost: d(sc.constructionCost),
    en15459ComponentIndex: sc.en15459ComponentIndex,
  }))
  buildingElementMaintenancePercent: d(variant.maintenanceConfig?.buildingElementMaintenancePercent)
  wlcInput: map from variant.wlcInput fields to WLCInputData (also compute designCostsTotal and siteManagementCostsTotal from designCosts array)
  designCosts: variant.designCosts.map(dc => ({
    lineNumber: dc.lineNumber,
    description: dc.description,
    preliminaryCost: d(dc.preliminaryCost),
    definitiveCost: d(dc.definitiveCost),
    executiveCost: d(dc.executiveCost),
    siteManagementCost: d(dc.siteManagementCost),
  }))
  incomeInput: convert IncomeInput flat fields to IncomeInputData grouped format:
    rents: [ {monthlyPerM2: d(rent1MonthlyPerM2), area: d(rent1Area), taxes: d(rent1Taxes)}, ... for rent2, rent3 ]
    otherIncomes: [ {amount: d(otherIncome1), taxes: d(otherIncome1Taxes)}, ... for other2, other3 ]
    expectedPricePerM2: d(expectedPricePerM2)
    Only include if any rent or income value is non-zero; otherwise pass undefined
  ```

  For `wlcInput.designCostsTotal`: sum all design costs' (preliminary + definitive + executive)
  For `wlcInput.siteManagementCostsTotal`: sum all design costs' siteManagementCost

Create `calculationRouter` with:

1. **calculate** - `protectedProcedure.input(z.object({ variantId: z.string(), formulaMode: z.enum(["excel_replica", "excel_bugfixed"]).default("excel_bugfixed") })).query()`:
   - Per user decision: Viewer CANNOT trigger calculations. Check that user is OWNER or EDITOR.
   - Load variant with ALL relations in a single query (avoid N+1):
     ```
     ctx.db.variant.findUnique({
       where: { id: input.variantId },
       include: {
         project: { select: { id: true, userId: true, members: { select: { userId: true, role: true } } } },
         geometry: true,
         boundaryCondition: true,
         energyInputs: true,
         costItems: { include: { details: true } },
         serviceComponents: true,
         wlcInput: true,
         designCosts: true,
         incomeInput: true,
         maintenanceConfig: true,
       },
     })
     ```
   - If variant not found, throw NOT_FOUND
   - Verify user is project creator or OWNER/EDITOR member. If not, throw NOT_FOUND.
   - Verify variant has required data (boundaryCondition exists). If missing, throw BAD_REQUEST with user-friendly message "Missing boundary conditions - please complete the WLC step first."
   - Build VariantInput using `buildVariantInput(variant)`
   - Run `calculateLCC(variantInput, { formulaMode: input.formulaMode, maxReplacementCycles: DEFAULT_ENGINE_CONFIG.maxReplacementCycles })`
   - Wrap in try/catch. On engine error: throw `TRPCError({ code: "BAD_REQUEST", message: "Calculation failed - please check your inputs." })` (per user decision: user-friendly messages only, hide engine internals)
   - Return the full `LCCResult`
   - NOTE: Per user decision, do NOT persist ResultSnapshot on auto-calc. Snapshot creation happens on explicit export/save (Phase 9).

**FormulaMode conversion:** The tRPC input uses lowercase (`"excel_replica"`, `"excel_bugfixed"`) matching the engine's `FormulaMode` type directly. No conversion needed for the engine. Conversion to Prisma SCREAMING_CASE (`EXCEL_REPLICA`, `EXCEL_BUGFIXED`) only needed when storing to DB (not in this phase since we don't persist snapshots on auto-calc).
