<task type="auto">
  <name>Task 1: Create initial migration and configure seed</name>
  <files>prisma/migrations/*, package.json</files>
  <action>
  1. Ensure Docker PostgreSQL is running: `docker compose up -d` and wait for pg_isready.

  2. Add the `prisma.seed` configuration to package.json. Prisma 7 requires this to know how to run the seed script. Add at the top level of package.json (sibling to "scripts"):
     ```json
     "prisma": {
       "seed": "npx tsx prisma/seed.ts"
     }
     ```

  3. Create the initial migration:
     ```bash
     npx prisma migrate dev --name init
     ```
     This generates the migration SQL in `prisma/migrations/<timestamp>_init/migration.sql` and applies it.
     If it fails because tables already exist from a prior `db push`, reset first:
     ```bash
     npx prisma migrate reset --force
     ```
     Then re-run `npx prisma migrate dev --name init`.

  4. Run the seed script to verify it works:
     ```bash
     npx prisma db seed
     ```
     Expected output: "Seeded demo user: demo@lcczero.dev" and "Seeded project: ... with 3 variants".

  5. Verify tables were created by checking migration SQL contains CREATE TABLE statements for all major models: User, Session, Account, Verification, Project, ProjectMember, Variant, Geometry, BoundaryCondition, EnergyInput, CostItem, CostItemDetail, ServiceComponent, WLCInput, DesignCost, IncomeInput, MaintenanceConfig, ResultSnapshot, ProjectRevision, ExportRecord.
  </action>
  <verify>
    <automated>npx prisma migrate status</automated>
  </verify>
  <done>Migration applied, all tables exist, seed completes with demo user + 3-variant project logged to console</done>
</task>

  1. Start PostgreSQL
  2. Generate Prisma Client

  Change step [3/4] to [3/5] (migrations), add a new step [4/5] (seed), and renumber [4/4] to [5/5] (dev server).

  The seed step should be:
  ```batch
  echo [4/5] Seeding database...
  call npx prisma db seed
  if errorlevel 1 (
      echo [ERROR] prisma db seed failed.
      pause
      exit /b 1
  )
  echo.
  ```

  Also update the step numbers for the existing migration step ([3/4] becomes [3/5]) and dev server step ([4/4] becomes [5/5]).

  Note: `prisma migrate dev` in run.bat should be changed to `prisma migrate deploy` for a startup script — `migrate dev` is interactive and creates new migrations, while `migrate deploy` just applies existing ones. This is safer for a "run the project" script.
