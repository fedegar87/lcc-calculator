Create `prisma/seed.ts` as the main seed script entry point.

**PrismaClient initialization** (must use PrismaPg adapter per DEC-014):
```typescript
import { PrismaClient } from '../src/generated/prisma/client';
import { PrismaPg } from '@prisma/adapter-pg';
import { hashPassword } from 'better-auth/crypto';

const connectionString = process.env.DATABASE_URL;
if (!connectionString) {
  console.error('DATABASE_URL environment variable is required');
  process.exit(1);
}

const adapter = new PrismaPg({ connectionString });
const prisma = new PrismaClient({ adapter });
```

**Import seed data** from `prisma/seed-data/` files.

**main() function flow:**

1. **Hash password:**
   ```typescript
   const hashedPassword = await hashPassword(DEMO_USER.password);
   ```

2. **Upsert demo user** (idempotent):
   ```typescript
   const user = await prisma.user.upsert({
     where: { email: DEMO_USER.email },
     update: { name: DEMO_USER.name },
     create: {
       name: DEMO_USER.name,
       email: DEMO_USER.email,
       emailVerified: true,
     },
   });
   ```

3. **Upsert credential account** for Better Auth:
   - Better Auth requires an Account record with `providerId: 'credential'`, `accountId: user.id`, `password: hashedPassword`
   - Use a deterministic ID: `seed-credential-${user.id}` for idempotent upsert
   ```typescript
   await prisma.account.upsert({
     where: { id: `seed-credential-${user.id}` },
     update: { password: hashedPassword },
     create: {
       id: `seed-credential-${user.id}`,
       userId: user.id,
       providerId: 'credential',
       accountId: user.id,
       password: hashedPassword,
     },
   });
   ```

4. **Delete existing demo project** (idempotent re-seed -- cascade deletes all variants/costs):
   ```typescript
   await prisma.project.deleteMany({
     where: { name: PROJECT_META.name, userId: user.id },
   });
   ```

5. **Create project with nested variants:**
   - Each variant uses nested `create` for: geometry, boundaryCondition, energyInputs, costItems, serviceComponents, wlcInput, designCosts, incomeInput, maintenanceConfig
   - Pass BOUNDARY_CONDITIONS as the `energyPrices` Json field value
   - Map seed data objects to Prisma create input shapes

   Key mapping notes:
   - `boundaryCondition.energyPrices` is a Json field: pass the array directly
   - `incomeInput` uses flat fields: `rent1MonthlyPerM2`, `rent1Area`, `rent1Taxes`, `otherIncome1`, `otherIncome1Taxes`
   - `wlcInput` maps: `landCost` -> `landPrice`, `enablingCosts` -> `enablingCost1`, `planningFees` -> `planningFees1`
   - `costItems` maps: `materialCost` -> `materialCostAgg`, `laborCost` -> `laborCostAgg`, `otherCost` -> `otherCostAgg`
   - For `energyInputs`: when endUse is PV_PRODUCTION, set both `specificConsumption` AND `pvProductionKwh`

6. **Create ProjectMember** linking user as OWNER:
   ```typescript
   await prisma.projectMember.create({
     data: { projectId: project.id, userId: user.id, role: 'OWNER' },
   });
   ```

7. **Console output** for verification:
   ```typescript
   console.log(`Seeded demo user: ${user.email} (id: ${user.id})`);
   console.log(`Seeded project: ${project.name} with 3 variants`);
   ```

**Script wrapper:**
```typescript
main()
  .then(async () => { await prisma.$disconnect(); })
  .catch(async (e) => {
    console.error('Seed failed:', e);
    await prisma.$disconnect();
    process.exit(1);
  });
```
